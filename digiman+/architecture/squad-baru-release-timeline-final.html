Kenapa 3 Backend — Bukan Cukup Nambah FE/QA Saja

Dari eksplorasi skenario headcount sebelumnya: menambah FE dan QA saja (tanpa nambah BE) tidak cukup untuk kompresi signifikan selama freeze code diberlakukan (tidak ada cicil antar rilis) — karena BE (2 orang) selalu jadi critical path di tiap rilis, FE/QA ekstra cuma menunggu BE selesai duluan. BE harus ikut ditambah supaya benar-benar berhenti jadi bottleneck di kedua rilis.

Kenapa ~12 → 19 → 16 Minggu — Perjalanan Angkanya

Estimasi awal skenario final (13 minggu) mengasumsikan QA baru mulai setelah 100% dev rilis selesai ("big bang" testing). Realistisnya, task-task dalam satu rilis tidak semua selesai di hari yang sama — beberapa modul (Inspection, Order Approval, Master Data) code-complete lebih dulu daripada modul terbesar (Digiplan/SAP Sync). QA tidak perlu menunggu modul terakhir selesai untuk mulai testing modul yang sudah jadi — testing bertahap (shift-left) ini awalnya memangkas ~1 minggu di tiap rilis (13→11 minggu).
